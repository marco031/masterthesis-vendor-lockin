# From Dyads to Networks: Vendor Lock-in and Systemic Vulnerability in German Public IT Procurement

Code and processed data for the master's thesis of Marco Stoehr.

The thesis examines whether prior contracting between German contracting authorities and IT suppliers predicts subsequent awards (path dependence at the level of the buyer-supplier dyad) and whether the resulting structure makes the procurement network vulnerable to the loss of central suppliers. It combines a descriptive network analysis, panel regressions on buyer-supplier opportunity sets and a supplier-removal simulation, based on TED Contract Award Notices (CAN) for 2009-2023 in three CPV segments: hardware (CPV 30), software (CPV 48) and IT services (CPV 72).

## Requirements

Tested with **Python 3.13.9**. The notebooks require Jupyter (e.g., via VS Code or `pip install jupyter`). Install the package dependencies with:

```bash
pip install -r requirements.txt
```

## Data

The raw data are the TED CSV open data files published by the European Commission (Directorate-General for Internal Market, Industry, Entrepreneurship and SMEs):

https://data.europa.eu/data/datasets/ted-csv?locale=en

The data used in the thesis were downloaded on 20 April 2026. Since the published files may be revised over time, a later download may differ slightly from the data used here.

Download the Contract Award Notice files for 2009-2023 and place them in `can_data/` as

```
can_data/export_CAN_<YYYY>.csv
```

with one file per year.

Because of their size, neither the raw files in `can_data/` nor the intermediate files in `data_checkpoints/` are included in this repository. Both folders are included empty; the checkpoint files are regenerated from the raw data when the notebooks are run in order.
For the same reason, the opportunity-set panels of the regression (`data_analysis/panel_cpv30.csv`, `panel_cpv48.csv`, `panel_cpv72.csv`) are not included; they are generated by `04_panel_regression`.

## Running the analysis

Run the notebooks in numerical order. Each notebook reads the output of the previous ones and starts with a header describing its purpose, inputs and outputs.

| Notebook | Content |
|---|---|
| `01_data_cleaning` | Removal of non-informative records, splitting of multi-supplier and multi-buyer entries, entity resolution, parent mapping |
| `02_deduplication_variable_preparation` | Check of framework agreements and call-offs; construction of the dyad-year dataset |
| `03_descriptive_analysis` | Network size, degree distributions, tie persistence, repeat-tie share, concentration, filtered networks |
| `04_panel_regression` | Opportunity sets, relational history variables, segment and pooled linear probability models (H1a-H3) |
| `05_resilience_analysis` | Sequential supplier removal (lock-in-based, degree-based, random) on aggregated bipartite networks (H4) |

The intermediate files written to `data_checkpoints/` allow later steps to be rerun without repeating earlier ones.

## Reproducibility notes

- Random removal in the resilience analysis uses 100 iterations with seed 42.
- The opportunity sets of the panel regression comprise about 8.3 million dyad-years. Running notebook 04 requires a considerable amount of memory.
- Contract values are not used anywhere in the analysis because of their insufficient data quality.
